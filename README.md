# task_man

ブラウザで動く、ひとり用のタスク管理アプリ。
「すぐやる / 近いうちにやる / 将来やる」の 3 段階でタスクを持ち、週のタイムラインに並べて
その週にどれだけ抱えているかを見るための道具です。展示会や締切のような予定（イベント）を登録して、
そこまでに終わらせたいタスクを紐づけることもできます。

仕様は使いながら決めていく前提なので、データは 1 つの JSON にまとまっていて
いつでもエクスポート・インポートできます。
作り始めたときの要件メモは [docs/initial-spec.md](docs/initial-spec.md) にあります（いまの仕様はこの README のほうです）。

## 動かす

Node.js 18 以上が必要です（開発は v22 で確認しています）。

```sh
npm install
npm run dev      # http://localhost:5172/
```

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバー |
| `npm run build` | 型チェックと本番ビルド（`dist/`） |
| `npm run preview` | ビルド結果の確認 |
| `npm test` | 日付・見積もり・集計・イベント・インポート検証の単体テスト |
| `npm run typecheck` | 型チェックのみ |
| `npm run expand` | 定期イベントの回を state.json に置く（足すものが無ければ書き込まない） |

ビルドすると `dist/` は静的ファイルだけになるので、そのままどこかに置いても動きます
（その場合、保存先は localStorage だけになります）。

データの置き場所は既定でリポジトリ直下の `data/` です。実際に使うデータは開発用のリポジトリから切り離しておくと、
開発中の操作やテストで壊す心配がありません。`.env.local`（git 管理外）に置き場所を書くと、そちらを読み書きします。

```sh
# .env.local
TASK_MAN_DATA_DIR=~/TaskManData   # 絶対パス、~/ から、またはプロジェクトルートからの相対パス
```

起動時のログに `➜  データ:  …/state.json` と実際の場所が出ます。

## 5 つの画面

**ボード** — 段階ごとの一覧。カンバン（横 3 列）とリスト（縦積み）を切り替えられます。
カードはドラッグで並べ替え・段階の移動ができ、他のカードのサブタスク欄に落とすとサブタスクになります。
逆にサブタスクを段階カラムに落とすと独立したタスクに戻ります（入れ子は 1 段まで）。

**週** — 月曜から日曜の 7 列を、**今週とその次の週の 2 週分**縦に並べます。左の「未配置」からドラッグして日に置きます。
各日のヘッダに見積もりの合計、その下に段階の色で積み上げたバーが出ます。
バーの地の部分が「1 日の目安」（既定 6h、右上で変更可）で、超えると合計が赤くなり超過位置に線が入ります。

**親を日に置くと、日を決めていないサブタスクもその日の親の中に入れ子で並びます。**
未配置の欄からはまとめて消えるので、どこへ行ったか分からなくなりません。
子だけ別の日にしたいときは、その入れ子の行を掴んで別の日へドラッグします。
未配置の欄へ戻せば、また親の中に収まります。

見積もりは置いた当人の日に数えるので、**親が抱えるのは日を決めていない子の分だけ**です
（例: 1h + 2h の子を持つ親を月曜に置き、2h の子だけ水曜へ動かすと、月曜 1h / 水曜 2h になります）。

**月** — 日ごとの配置件数と合計時間、その日のイベント名。セルを押すとその週の週ビューに移ります。
セルにマウスを乗せると、その日に何が入っているか（イベント・タスク・サブタスク・合計）が出ます。
右上の「今月 / +1ヶ月 / +2ヶ月 / +3ヶ月」で 3 ヶ月先まで一押しで飛べます（前の月・次の月でさらに先へも行けます）。

**イベント** — 展示会や締切など、タスクそのものではない予定。終日か開始・終了時刻を持ち、
終了日を入れれば合宿や出張のように複数日にまたがることもできます
（日をまたぐときは、開始時刻は初日の、終了時刻は最終日のものとして扱います）。
タスクの詳細から 1 件だけイベントを紐づけられ、イベント画面ではそのタスクの進み具合（3/5 完了・合計時間）が出ます。
紐づけたイベントは、ボードのカードに「10/12–10/14 展示会 あと3日」のバッジ、週ビューは各日の上部の帯、
月ビューはセルの中の名前として出ます。複数日のイベントはかかっている日すべてに帯が出て、
始まってから終わるまでは「開催中」として一覧の「これから」に残ります。
イベントを削除してもタスクは消えず、紐づけが外れるだけです（トーストから取り消せます）。
予定が無くなったときは「中止にする」で、消さずに中止として残せます（取り消し線で出て、残り日数などには数えません）。

**定期** — 「毎週 火・木 10:00–11:00」のような毎週の予定は、イベント画面の「定期」の欄から足します。
曜日（複数可）・時刻・開始日・終了日（空なら終わりなし）を決めると、**今日から 2 ヶ月先までの回が通常のイベントとして置かれ**、
日が進むにつれて先の回が足されていきます（アプリの起動時。`npm run expand` でも置けるので、起動スクリプトから先に呼んでおくこともできます）。
置かれた回は 1 件ずつ日付や時刻を変えられ、変えた回は、あとで定期の時刻などを変えてもそのまま残ります（変えていない回は新しい設定に合わせます）。
定期の回は削除の代わりに「中止」にします。消してしまうと次にまた置かれてしまうためで、中止の回は二度置かれません。
定期そのものを消すと、今日以降の回は中止になり、どの回も単発のイベントとして残ります。

**たのしみ** — 見たい映画、やりかけのゲームなど、タスクではない楽しみの控え。
「気になる / 進行中 / 中断」の 3 列と、畳んである「済・やめた」に分かれます。
カードの「始める」「済にする」「再開」で一押しで進められ、中断・やめたは詳細から選びます。
カードは持ち手（⋮⋮）を掴んでドラッグすると並べ替えられ、別の列に落とすと状態も変わります。
「済・やめた」は 0 件でも開けて、開いていればそこにも落とせます。
新しく足したものとボタンで状態を変えたものは、その列の先頭に入ります。
詳細には「どこまで」（4章まで、S2E5 など）、「どこで」（Netflix、Switch など）、評価（★1〜5）、メモを書けます。
初めて進行中にした日と済にした日は自動で記録されます。
見積もりも日付も持たないので、ボードや週・月のカレンダーには出ず、負荷の計算にも入りません。

種類（映画・ゲーム・本・アニメが最初から入っています）は、上の帯の「種類を編集」で追加・名前の変更・色の変更・削除ができます。
帯の種類を押すとその種類だけに絞り込めます。種類を消しても中身は消えず、未分類になります（トーストから取り消せます）。

## 覚えておくと早い操作

| キー | 動き |
| --- | --- |
| `1` `2` `3` `4` `5` | ボード / 週 / 月 / イベント / たのしみ |
| `/` | 検索へ |
| `n` | 一番近いタスク追加欄へ |
| `Esc` | 詳細パネルを閉じる、検索を消す |

見積もりの入力は `1.5h` `90m` `1h30` のほか、単位なしの `2` は 2 時間として読みます。

## データの持ち方

`npm run dev` で動かしているあいだは、**操作するたびに `state.json` へ自動保存**されます（置き場所は上の `TASK_MAN_DATA_DIR`、既定は `data/`）。
ヘッダーの右側に保存の状態（`ファイルに保存 10:41` など）が出ます。

```
data/（または TASK_MAN_DATA_DIR）
  state.json                    いま開いているデータ。これが正
  archive.json                  削除した完了済みタスクの記録（削除のたびに末尾へ追記）
  history/
    state-2026-09-19.json       その日の最初の保存時点。60 日分まで残る
```

- **起動時はファイルを読みます。** 別のブラウザやプロファイルで開いても同じデータになりますし、
  `state.json` をエディタで直接編集したり、git で履歴を取ることもできます。
- ファイルが無ければ localStorage（キー `task_man.state`）の内容で始まり、次の保存でファイルが作られます。
- ビルドして静的に配信した場合は保存 API が無いので、表示が「ブラウザ内に保存」になり localStorage だけを使います。

### ファイルを直接編集するとき

画面を開いたままファイルを書き換えると、次の保存で**競合として検出**され、ヘッダーに
「ファイルが更新されています」と 2 つのボタンが出ます。

- **ファイルを読む** — ファイルの内容で画面を読み直す（画面側の変更は失われます）
- **こちらで上書き** — 画面の内容でファイルを書き換える（ファイル側の変更は失われます）

黙ってどちらかを消すことはしません。安全に編集したいときは、タブを閉じてから書き換えてください。

### 手動のバックアップ

- **エクスポート** — `task-man-backup-YYYY-MM-DD.json` を保存します。
- **インポート** — 中身を確認してから現在のデータを置き換えます。読み込んだ直後なら「元に戻す」で戻せます。
- 足りないフィールドは既定値で補い、親が居ないサブタスクや 2 段以上の入れ子、
  消えたイベントを指したままの紐づけは読み込み時に直します。
- `events` を持たない古いバックアップも読めます（イベント 0 件として開きます）。
- `mediaKinds` / `media` を持たない古いバックアップは、既定の種類とたのしみ 0 件で開きます。

削除・完了済みの一括削除・インポートは、いずれも画面下のトーストから取り消せます。

### 完了済みタスクのアーカイブ

完了済みタスクは削除しても消えず、`archive.json` に追記されます。対象は「完了済みを削除」と、
完了済みのタスクを詳細パネルから削除したとき（サブタスクも一緒に残ります）。未完了のタスクの削除は従来どおりです。

- 1 回の削除が 1 件のエントリになり、`archivedAt`（日時）・`reason`（`clear-completed` / `delete`）・`tasks` に加えて、
  あとでタグやイベントを消しても読めるよう、そのとき参照していた `tags` / `events` を写して持ちます。
- トーストから取り消すと、そのとき足したエントリも `archive.json` から外れます。
- 送れなかった分は localStorage（キー `task_man.archive.pending`）に残り、次の起動時や次の削除時に送り直します。
  静的に配信した場合はファイルに送れないので、ここがそのままアーカイブになります。

## 中身

Vite + React + TypeScript。状態は zustand（`persist` で localStorage へ）、
ドラッグは `@dnd-kit`。UI ライブラリは使わず、色は `src/styles/tokens.css` の CSS 変数にまとめてあります。

```
scripts/
  expand-recurring.ts state.json に定期の回を置く（npm run expand）
server/
  stateFile.ts        state.json の読み書き、日次スナップショット、競合の判定
  archiveFile.ts      archive.json への追記・取り消し
  vitePluginStateFile.ts  dev サーバーに /api/state と /api/archive を足すプラグイン
src/
  types.ts            タスク・イベントとアプリ状態の型
  store/
    useAppStore.ts    状態と操作（追加・移動・配置・取り消し）
    persist.ts        既定値、スキーマ検証、移行
    selectors.ts      絞り込み・並び替え・集計（配置分の数え方もここ）
    transfer.ts       エクスポート / インポート
    fileSync.ts       state.json との同期（自動保存・競合検出）
    archive.ts        削除した完了済みタスクを archive.json へ送る
  lib/                日付・見積もり・並び順・ドラッグの補助、定期の展開（recurrence.ts）
  components/
    shell/            ヘッダ、絞り込み、テーマ、ショートカット
    board/            カード、サブタスク、詳細パネル
    week/             日カラム、積み上げバー、未配置ペイン
    month/            月カレンダー
    event/            イベント一覧・詳細パネル、定期
    media/            たのしみの一覧・詳細パネル・種類の編集
    common/           バッジ、確認ダイアログ、トーストなどの共通部品
```

段階を増やしたい、フィールドを足したいといった変更は `types.ts` と `store/persist.ts` の
`makeTask` / `makeEvent` / `parseAppData` を起点にすると追いやすいはずです。
保存データの形を変えるときは `SCHEMA_VERSION`（現在 4）を上げて `migrate` に移行を足してください。
